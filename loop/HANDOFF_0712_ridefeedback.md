## 2. ⚠️⚠️ 최우선 미완료 작업 — 사용자 실주행 피드백 PDF, 분석 못 함

사용자가 위 체크리스트를 들고 실제로 라이딩(편의점 왕복 + 이후 더 먼 거리)을 다녀왔고,
**스크린샷에 빨간 원/화살표로 직접 주석을 단 15~16페이지 분량의 PPT를 PDF로 변환해서
세션에 올렸다.** 이 세션은 그 직후부터 `API Error: Unable to connect to API (ECONNRESET)`가
약 3시간 넘게 반복되며 사실상 죽었고, 사용자가 몇 번 재시도(`작업재개해라`, `Continue from
where you left off`)했지만 전부 실패했다. 마지막엔 사용자가 "PDF 올린 건 무시하고 핸드오프나
만들어달라"고 했지만 그 요청조차 API 에러로 처리되지 못한 채 세션이 끝났다.

**즉 이 실주행 피드백은 아직 한 줄도 분석되지 않은 상태다.** 이게 다음 세션의 최우선 작업.

- **PDF 원본을 복구해서 저장해뒀다**: `loop/feedback/260712_testDriveFeedback.pdf`
  (원본 파일명 `260712_testDriveFeedback.pdf`, 죽은 세션의 대화 로그에 base64로 남아있던
  걸 추출함). **git에는 커밋 안 함**(스크린샷 포함 바이너리, 개인 라이딩 경로 노출 가능성
  — 커밋 여부는 사용자에게 먼저 확인). Read 툴로 페이지 단위 조회 가능하나, 이 서버엔
  `poppler-utils`(pdftoppm)가 없어서 **이 환경에서 직접 렌더링은 안 됨** — Claude가
  대화창에서 파일을 직접 첨부받는 방식(사용자가 올리는 방식)으로만 실제 내용을 볼 수 있었음.
  다음 세션에서 poppler-utils를 설치하거나(`sudo apt-get install poppler-utils`, 세션 시작
  시 sudo 비번 필요해서 이번엔 못 함), 사용자에게 같은 PDF를 다시 첨부받는 것 중 하나가
  필요함.
- **죽기 직전에 확인된 유일한 단서**: 사용자가 읽어달라고 한 직후, 모델이 PDF를 실제로
  읽고(15/16페이지, 스크린샷 주석까지 확인) "**전통시장/대형마트 칩이 나오는 화면**이
  결정적 단서"라고 언급하며 현재 코드를 확인하러 감. 확인 결과: **현재 코드엔 `전통시장`/
  `대형마트`/`traditionalMarket` 관련 텍스트가 전혀 없음(13-1 구현 때 이미 전부 제거됨,
  이 API가 해당 업종코드를 지원 안 해서 — `project_poi_datasource.md` 메모리 참조)**.
  즉 사용자가 스크린샷에서 지적한 "전통시장/대형마트" 칩은 **이미 폐기된 구버전 APK**에서
  캡처됐을 가능성이 높다는 뜻 — 실제 남은 버그인지, 오래된 빌드로 테스트해서 생긴 유령
  이슈인지 구분이 필요하다는 게 죽기 직전 모델의 판단이었다. 다음 세션은 이 구분부터 다시
  해야 함(코드는 그대로이므로 결론 자체는 유효할 가능성이 높지만, PDF를 직접 봐야 다른
  페이지의 지적사항도 같은 패턴인지 확인 가능).
- 사용자 지시(마지막으로 받은 것): "잘 읽고, 의문점은 나에게 바로 물어봐서, 문제를

  방안을 정리하는 순서로 진행할 것.
- 세션 도중 모델이 opus로 전환됨(`/model opus`, 사용자가 직접 실행) — 이 PDF 분석 작업
