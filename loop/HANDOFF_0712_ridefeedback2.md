# HANDOFF — YuruNavi (2026-07-12, 실주행 피드백 PNG 분석 이어받기)

> **이 문서는 `HANDOFF_0712_ridefeedback.md`의 §2/§3을 대체함.** 그 문서가 "PDF를 읽어야

## 1. ⚠️ PDF는 절대 열지 말 것

`loop/feedback/260712_testDriveFeedback.pdf`를 Read 툴로 열거나 poppler-utils를 설치해서
렌더링하면 **`API Error: Unable to connect to API (ECONNRESET)`가 반복되며 세션이 죽는다** —
사용자가 직접 확인해서 알려준 사실(2026-07-12). 이번 세션도 실제로 poppler-utils 미설치 확인
→ 설치 시도(sudo 필요해서 실패) → 사용자가 "PDF 읽지 마라, 그것 때문에 지난 세션이 죽었다"고
멈춤. **메모리에도 기록해둠**: `~/.claude memory`의 `feedback_no_pdf_reading.md` 참조.

**대신 사용자가 같은 내용을 PNG 16장으로 변환해서 올려줬다**: `loop/feedback/`에
`260712_testDriveFeedback_1.PNG` ~ `_16.PNG`. PNG는 Read 툴로 정상적으로 열림(이번 세션에서
1~9번 확인 완료, 문제없었음). **PDF 파일 자체는 여전히 같은 폴더에 있으니 절대 건드리지
말 것** — PNG만 사용.

## 2. 진행 상황 — 16장 중 9장 분석 완료, 이 세션도 그 도중 다시 API 에러 발생

PNG를 여는 것 자체는 문제없이 잘 되고 있었는데, 9번째 이미지를 읽은 직후 사용자가 "또
에러난다"고 알려왔다(PDF 때와 유사한 증상). 사용자 판단으로는 **세션이 길어지며 쌓인
컨텍스트(세션 메모리) 자체가 원인일 가능성**이 있다고 봄 — PNG 자체가 원인이 아닐 수 있다는
뜻. 그래서 나머지(10~16번)는 **새 세션에서 이어가기로 함**.

- **슬라이드별 상세 분석은 전부 `loop/feedback/ANALYSIS_progress.md`에 저장되어 있음** —
  다음 세션은 이 파일부터 읽을 것. 1~9번 요약 + 남은 작업(10~16번, 사용자 질문, 버그
  목록화)이 다 적혀 있다.
- **아래는 9번까지 나온 핵심 요지만 재정리**(전체 근거/맥락은 `ANALYSIS_progress.md` 참조):

**치명적 버그로 보이는 것**
1. 실제 내비게이션 안내 화면에서 POI 점이 아예 안 뜸(홈 화면엔 뜨는데 내비 화면만 안 뜸) —
   "주행 중 가까운 주유소/카페 찾기"라는 핵심 시나리오라 사용자가 가장 심각하다고 지목.
2. 마트/식당 카테고리 칩을 눌러도 리스트가 전부 주유소 항목만 나옴 — 카테고리 필터링이
   사실상 깨진 것으로 보임.
3. 카페 칩인데 "할매국물닭발", "신창마을관리사회적협동조합" 같은 비카페 결과가 섞여나옴.
4. 카테고리 칩셋 자체가 두 가지 버전으로 뒤섞여 등장 — `카페/편의점/주유소/마트/식당`(현재
   코드가 맞다고 알고 있던 5종) vs `주유소/전통시장/대형마트/식당`(전통시장 포함, 현재
   코드엔 없어야 하는 카테고리). **지난 세션 죽기 직전엔 "이건 이미 폐기된 구버전 APK
   캡처일 것"이라 추정했는데, 이번에 실제 스크린샷으로 두 버전이 뒤섞여 나오는 걸 사용자가
   보여줬다 — 그 추정이 틀렸을 가능성이 있으므로 코드/캐시/설치 상태를 재조사 필요.**
5. 번화가에서 "화면당 최대 10개" 제한이 깨지고 수십 개가 한꺼번에 표시되는 경우가 있음.

**UX 개선 요청(버그는 아니지만 명시적 요청)**
- 앱 시작 시 POI 로딩 5초+ 걸림 → 스플래시 중 백그라운드 프리로딩 요청.
- 점 정렬이 거리순이 아니라 랜덤처럼 보임, 점에 아이콘+이름 없음(네이버지도 스타일 참고
  이미지 있음), 점 자체가 터치 안 됨.
- 10개 제한 시 우선순위(주유소>편의점>카페>대형마트>전통시장) 요청, 10→20개 상향 요청,
  화면 전체에 고르게 분포(현재는 중앙에만 몰림) 요청.
- 리스트 항목 탭 시 확인 없이 바로 목적지로 잡힘 → 카드+버튼(목적지 설정/경유지 설정)으로
  바꿔달라는 요청. 목적지/경유지 지정 시 지도 포인터 아래 이름 라벨 필요.
- 검색이 앞글자(prefix)만 매칭, 부분 문자열 검색 안 됨. 검색창 포커스 시 키보드에
  바텀시트가 가려짐. 검색 결과가 "화면 중심"이 아니라 "GPS 내 위치 중심"으로 나옴(지도를
  다른 지역으로 옮긴 뒤 검색해도 여전히 내 위치 기준 — 사용자는 화면 중심 기준을 원함).
  로딩 속도 개선 요청(백그라운드 프리페치, 데이터 사용량 신경쓰지 말라고 명시).

**긍정 피드백(추가 조치 불필요, 확인만 해두면 됨)**
- 도로 표시(굵기/라벨/번호배지) 개선 만족.
- **코너 진입 "곧 좌/우회전" 음성 타이밍 — "완벽하게 잘 해결됨"이라고 확인.** 이건
  `HANDOFF_0712_poi.md` §4에서 "스펙 불명확, 사용자에게 재확인 필요"로 남아있던
  **CORNER-VOICE-50M 항목이 실주행으로 검증 완료됐다는 뜻**으로 보임 — 다음 세션에서 이
  항목을 BLOCKED/재확인 대상에서 제외해도 될지 사용자에게 짧게 확인만 하면 될 듯.

**기타**
- 사용자가 버그를 우리가 직접 GPS 시뮬레이션으로 재현/수정하길 제안함 — 필요하면 헤드리스
  서버에 모니터 연결도 가능하다고 함(집에 여분 모니터 있음). 참고용 주행 속도 프로필: 국도
  최고110/평균50km/h, 지방도 최고80/평균40km/h, 시골길 최고60/평균30km/h.
