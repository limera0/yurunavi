## 1. 이미 확정된 사실 (다시 조사하지 마라)

### 1-A. S1(clamp 예외)이 **아니다** — 픽셀 실측으로 확정

Flutter 릴리스 빌드의 기본 `ErrorWidget`은 오류 난 자리를 단색으로 덮는다.
색은 SDK 소스에 박혀 있다 — `packages/flutter/lib/src/rendering/error.dart:115`:

```dart
static Color _initBackgroundColor() {
  var result = const Color(0xF0C0C0C0);   // 릴리스: 밝은 회색
  assert(() { result = const Color(0xF0900000); return true; }());  // 디버그: 진한 빨강
  return result;
}
```

`0xF0C0C0C0`를 흰 배경 위에 합성하면 **(196,196,196)**이다.
스크린샷 실측값은:

| 위치 | 실측 RGB | ErrorWidget이라면 |
|---|---|---|
| 일출일몰 바 내부 | **(253,253,253)** | (196,196,196) |
| 속도계 원 내부 | **(255,255,255)** | (196,196,196) |
| (대조) 지도 배경 | (241,237,233) | — |
| (대조) 상단 카드 흰 배경 | (255,255,255) | — |

**순백이다. 위젯이 오류로 갈린 게 아니다.** 이 판정을 다시 뒤집으려 하지 마라 —
뒤집으려면 위 픽셀값을 반박해야 한다.

### 1-B. 관측된 현상 — "껍데기는 그려지고 알맹이만 사라진다"

- **속도계**: 주황 테두리 원이 **완벽하게** 그려짐. 안의 숫자만 없음
- **일출일몰 바**: 흰 알약 + 그림자 정상. 알파 0.95라 **뒤의 도로가 비쳐 보이기까지 한다**
  (= 진짜 `DaylightBar`의 `Container`가 그려지고 있다는 증거).
  그런데 해/달 아이콘·시간 라벨은 물론 **게이지 막대까지 없다.**
  ⚠️ 게이지 막대는 폰트·글리프가 아니라 **그냥 색칠한 `Container`**다.
  "글꼴 텍스처만 날아갔다"는 단순 가설로는 이게 설명되지 않는다
- **내 위치**: 파란 원만 남고 **방향 화살표 스프라이트 소실**.
  이건 Flutter가 아니라 **지도 엔진(MapLibre) 쪽**이다 → 두 엔진에서 동시 발생
- **반대로 정상 렌더된 것**: 상단 안내카드의 "555m / 서동대로 / 다음 우측…" 텍스트,
  지도 도로 라벨("서동대로"), 우측 버튼의 +/− 아이콘
  → **전면 실패가 아니라 부분 실패다.** 이 비대칭이 원인 추적의 핵심 단서다

## 2. 조사 순서

### 2-1. 1단계 — 재현 조건 확보 (**최우선. 이게 안 되면 나머지 전부 무의미**)

마스터 관측: **내비 실행 후 10분쯤** 발현. 이 "10분"이 시간인지, 주행거리인지,
누적 렌더 횟수인지, 특정 이벤트인지 **가르는 것이 1단계의 목표**다.

- **메모리 압박 인위 조성** — 마스터 환경(다른 앱 0개)보다 나쁜 조건을 만들어야 한다:
  - `adb shell am send-trim-memory <pid> RUNNING_MODERATE|RUNNING_LOW|RUNNING_CRITICAL`
  - 백그라운드 앱 다수 실행 후 주행
  - (가능하면) `adb shell settings put global ...` 류로 저사양 흉내 —
    **되는지 확인부터 하고, 안 되면 억지로 하지 마라**
- **가상GPS 장시간 주행 재생** — memory `project_vgps_testing` 준수:
  **GPS/NETWORK/FUSED 3-provider 모킹 필수.** 안 하면 60~100초마다 실제 좌표가
  섞여 들어와 데이터가 오염된다
- **계측 (주행 내내 주기적으로)**:
  ```
  adb shell dumpsys gfxinfo <pkg>        # GPU 메모리·프레임
  adb shell dumpsys meminfo <pkg>        # Graphics/GL 항목을 특히 볼 것
  adb logcat | grep -iE "vulkan|impeller|atlas|glyph|OutOfMemory|GL_OUT_OF_MEMORY|trim"
  ```
- **발현 시점 기록**: 경과시간 / 주행거리 / 그 직전 이벤트 / `meminfo` 추이
- **스크린샷 자동 수집** — 1분마다 `adb exec-out screencap -p`로 받아
  §1-A와 같은 방식(속도계 원 내부 픽셀값)으로 **자동 판정**하면 사람이 안 봐도 된다.
  판정 기준: 속도계 원 내부에 숫자 픽셀(어두운 값)이 있는가

### 2-2. 2단계 — 렌더러 변수 격리

Impeller가 유력 용의자이나 **확정 아니다.**

- Flutter 3.44에서 안드로이드 Impeller를 끄는 방법이 **현재도 유효한지 먼저 확인**하라
  (매니페스트 `<meta-data android:name="io.flutter.embedding.android.EnableImpeller"
  android:value="false"/>`. 버전에 따라 제거·변경됐을 수 있다 — **추측 말고 확인**)
- 동일 시나리오로 **on/off A/B**. 한쪽에서만 재현되면 렌더러 확정
- ⚠️ **Impeller를 끄는 것 자체를 해결책으로 커밋하지 마라.** 이 세션은 조사다.
  성능·품질 트레이드오프가 크고 마스터 판단이 필요하다

### 2-3. 3단계 — 메모리 압박 대응 부재 확인

- 앱에 `WidgetsBindingObserver.didHaveMemoryPressure()` 대응이 있는가 (없을 것으로 추정)
- 안드로이드 `onTrimMemory` 경로가 Flutter/MapLibre로 전달되는가
- 이미지 캐시(`PaintingBinding.instance.imageCache`) 상한이 기본값인가
- MapLibre 타일 캐시 정책 — **S2의 "1.65GB 배분 실측"과 같은 대상**이니 중복 조사 마라.
  S2가 아직 안 됐으면 여기서 같이 재고 결과를 양쪽에 남겨라

### 2-4. 4단계 — 방어 설계 제안 (문서로만. 구현은 다음 세션)

원인이 무엇으로 밝혀지든 **효과가 있는 것부터** 우선순위를 매겨 제안하라.

- 저사양·메모리압박 감지 → 품질 다운시프트
  (S5의 Thermal Governor 개념과 같은 계열 — **따로 만들지 말고 한 축으로 묶을 것**)
- 화면 밖 위젯의 불필요한 리빌드 제거 — 아래 2-5
- 캐시 상한 동적 조정

### 2-5. 같이 볼 것 — 내비 중 홈 화면이 살아있는 구조

S1 조사에서 발견됐다. `_startNavigation`은 **코스 시트를 닫지 않고** 내비 화면을
push하며, `_showCourseSheet = false`는 내비가 pop된 뒤 `_clearDestination()`에서야
실행된다. 즉 **주행 내내 홈 화면(지도 포함)이 시트 열린 상태로 밑에 살아있고,
GPS 1Hz마다 리빌드된다**(로그상 정확히 1.000초 간격으로 확인됨).

**메모리·GPU 자원을 이중으로 잡아먹는 구조이므로 S1b의 직접 후보다.**
지도 플랫폼뷰가 두 개 동시에 살아있는지 실측하라 — 사실이면 그것만으로 큰 건이다.

### 2-6. S1 수정 후 재측정 (**착수 전에 이것부터**)

clamp 예외 56,789건이 매번 스택트레이스 생성 + Crashlytics 업로드를 유발하고 있었다.
S1로 그게 멎었으니 **S1b의 빈도·발현시점이 달라졌을 수 있다.**
**S1 적용 빌드로 먼저 재현을 시도하고, 남은 만큼만 대응 대상으로 삼아라.**
