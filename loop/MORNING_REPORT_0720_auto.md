# 2026-07-20 밤 자동 실행 보고서 (14번 Crashlytics 감사 / 16번 구조물·급커브 카드)

## 한 줄 요약
오늘 밤 작업(14번, 16번)은 **거의 진행되지 않았다**. 자동화가 45분짜리 틱을 딱 1번
돌리자마자 API 연결 오류로 죽었고, 그 와중에 자동화 스크립트 자체의 버그 때문에
"작업 다 끝남(DONE)"으로 잘못 판단해서 조용히 멈춰버렸다. 사람이 개입하지 않으면
다음날 밤에도 똑같은 일이 반복될 수 있다.

## 오늘 밤 무슨 일이 있었나 (시간순)

1. **20:25** — `run_night_auto.sh`가 오늘 밤 작업 지시서(`loop/HANDOFF_0720_night_14_16.md`,
   14번·16번)를 갖고 틱 1을 시작함.
2. 틱 1이 **17분(1012초)** 돌아가다가 죽었다. 로그(`loop/.auto/logs/tick_1_2025.log`)에
   남은 내용은 딱 한 줄:
   ```
   API Error: Unable to connect to API (ECONNRESET)
   ```
   이건 CLAUDE.md에 이미 적혀있는 "알려진 문제"(anthropics/claude-code#51164) 그 자체다.
   짧은 틱으로 쪼개서 이 문제를 피하려고 만든 자동화인데, 정작 첫 틱에서 바로 걸렸다.
3. 죽기 전에 딱 **커밋 1개**는 만들어놨다:
   - `7ee75ed` `fix(gpsinjector): move ACCESS_MOCK_LOCATION to debug-only manifest`
   - 내용: `flutter build apk --release` 빌드가 gpsinjector 모듈(가짜 GPS 테스트용
     별도 모듈)의 권한 설정 때문에 실패하던 걸 고쳤다. 이건 14번 작업의 A단계
     ("release 모드에서 직접 빌드해서 확인해라")를 하기 **직전에 막힌 빌드 에러를
     치운 것**이지, 14번 작업 본체(Crashlytics 오분류 확인)는 아직 시작도 못 했다.
4. 틱이 죽으면서 **진행 메모 파일(`loop/.auto/handoff.md`)을 못 남겼다.** 그런데 이
   파일에는 오늘 낮 13:50에 자동화 스크립트 자체를 테스트해보려고 돌렸던 완전히
   다른(더미) 작업의 기록이 그대로 남아있었고, 그 첫 줄이 마침 `STATUS: DONE`이었다.
   자동화 스크립트는 "새 진행 메모가 있는지"를 확인하지 않고 **그냥 그 낡은 파일의
   첫 줄만 읽어서** "오늘 밤 작업 다 끝났다"고 착각하고 틱 체인을 멈춰버렸다.
   → **이건 자동화 스크립트 쪽 버그다.** 실제로는 14번도 16번도 거의 안 끝났는데
   "DONE"으로 잘못 보고된 것.
5. 그 다음 이 보고서를 쓰는 마무리 틱(20:41 시작)이 실행됐다 — 지금 이 문서가 그
   결과물이다.

## 왜 여기서 멈췄나 (원인 정리)

두 가지 문제가 겹쳤다:
1. **API 연결 끊김(ECONNRESET)** — 클로드 쪽 서버 문제로, 45분 틱 하나 안에서도
   여전히 발생할 수 있다는 게 확인됨. 완전히 없앨 방법은 없다(알려진 미해결
   이슈).
2. **자동화 스크립트가 "낡은 상태 파일"을 새 상태로 착각함** — 틱이 죽어서 진행
   메모를 못 남기면, 스크립트가 그 이전(오늘 낮 더미 테스트)의 메모를 그대로
   읽어서 "끝났다"고 오판하는 구조적 결함. 이번엔 우연히 그 낡은 메모의 첫 줄이
   `STATUS: DONE`이라서 더 위험했다 — 만약 그게 실수로 실제 작업 완료처럼 보이는
   내용이었다면, 사람이 아침에 보고서만 보고 "14번, 16번 다 끝났네"라고 오해할
   뻔했다.
