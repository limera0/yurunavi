### 결정 1 — 주행 알림 개수 (§2-5)

지금은 주행을 시작하면 상단에 **"알림 2개"**가 뜹니다. "유루나비 주행 중"(위치 수집용)과
"주행 안내"(내비 정보용) 두 개입니다.

- **방법 A**: "유루나비 주행 중" 알림을 없애고 "주행 안내" 하나만 남긴다.
  → 백그라운드에서 위치가 계속 잡히는지 **실기기 확인 필요**(서버에서는 못 함).
  잘못되면 백그라운드에서 내비가 멈춥니다.
- **방법 B**: 두 알림을 시스템이 합치게 만든다. → 알아본 결과 **기술적으로 불가능**
  (geolocator 라이브러리가 알림 채널 ID를 하드코딩해서 우리 코드에서 못 맞춤).
- **방법 C**: 그대로 둔다 — 배터리·성능 영향은 미미. 사용자가 알림 2개를 보게 됨.

**질문**: A / C 중 어느 쪽을 원하시나요? (A 선택 시 다음 날 밤 서버에서 코드는 수정하되,
실기기 검증은 마스터가 직접 해주셔야 합니다.)

### 결정 2 — PIP(작은 창) 복구 방법 (§2-7)

원본 피드백: *"PIP는 다른 방법으로 구현해야 함. PIP에서 복구하려면 화면 터치가 아니라
화면 우측의 작은 아이콘을 터치해야 함."*

두 가지로 해석됩니다:

- **해석 A**: 지금처럼 시스템 PIP 창을 쓰되, PIP 창을 눌러 복원되던 걸 **PIP 창 안의
  "복원" 버튼(우측 아이콘)만 눌러야** 되게 한다.
- **해석 B**: 시스템 PIP 자체를 없애고, 백그라운드에서는 **상단바 알림(또는 플로팅
  아이콘)만** 띄운 뒤 그걸 눌러야 앱이 복원되게 한다.

**질문**: A / B 중 어느 쪽인가요?

**중요**: 이번 밤 작업으로 **PIP가 잘못 뜨던 버그(알림창 내리기만 해도 PIP)** 자체는
이미 해결됐습니다. 위 질문은 그 다음 단계의 UX 설계입니다.

## 뭐가 됐나

밤 3틱을 돌려서 지시서의 세 청크를 다 끝냈습니다.

### 청크1 — 라이프사이클 오검출 근원 차단 (커밋 `a5beab1`, 21:37)

주행 중에 **알림창을 내리기만 해도 PIP(작은 창)로 튀어 안내가 끊기던** 버그의 원인:
Android가 알림창·스크린샷·엣지패널 조작에서도 `AppLifecycleState.inactive` 신호를
보내는데, 우리 코드가 그 신호를 "앱이 백그라운드로 갔다"로 오해석해 PIP를 강제
발동시켰습니다.

- `nav_screen.dart`에서 `AppLifecycleState.inactive`/`hidden` 분기를 통째로 삭제.
- PIP 진입은 이제 **홈 버튼 누름(Android가 정확히 알려주는 `onUserLeaveHint`)**과
  **Android 12+ Auto-PIP(전화 수신 등)** 두 경로만 남았습니다.
- 안드로이드 서비스가 시스템에 의해 강제 종료됐다 살아날 때 마지막 명령을 재전달받도록
  `NavForegroundService.kt`의 반환값을 `START_NOT_STICKY` → `START_REDELIVER_INTENT`로
  변경 (알림·주행 자동 복구).

### 청크2 — Wakelock 중복 제거 (커밋 `18da084`, 21:45)

RECON은 "wakelock이 3중으로 잡혀 배터리를 먹는다"고 했지만 실측 결과 **2중이 옳음**을
확인했습니다(안드로이드 서비스에는 wakelock 획득 코드 자체가 없었음). 그중 위치
라이브러리 쪽의 wakelock을 껐습니다. 화면 켜짐 유지(`WakelockPlus`)와 프로세스 유지
(포그라운드 서비스)만 유지됩니다.

### 청크3 — 지도 API 호출 가드 (커밋 `386a2f3`, 21:57)

로그에 `MissingPluginException` 예외가 **567건**(setGeoJsonSource 431 + camera#move 136)
쌓여 있었습니다. 원인: 지도 화면이 PIP나 dispose 상태로 넘어가면서 지도 위젯은 사라졌는데,
코드가 죽은 참조에다 계속 지도 갱신 명령을 날리고 있었습니다.

- `bool _canCallMap()` = `mounted && _mlCtrl != null && !_isInPip && !_isDisposing`
  게이트 함수 도입.
- dispose 시작 즉시 켜지는 `_isDisposing` 플래그 도입 (스트림 정리보다 먼저).
- 지도 호출 **19개소 전수 게이트 적용**.
- PIP 미니창은 지도 컨트롤러를 호출하지 않고 로컬 상태만 표시하는 걸 코드로 확인 →
  게이트가 미니창 정보 갱신을 막지 않음.
- 회귀 테스트 1건 신설 (`_isDisposing`이 정말로 스트림 close보다 먼저 세팅되는지 검증).
