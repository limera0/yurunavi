## 핵심 발견 — 조사 전제가 세션 도중 무너졌다

세션 시작 시 기기에 깔려 있던 빌드가 **S3b 이전**(`lastUpdateTime` 2026-08-05 20:40)이었다.
그런데 오늘 같은 브랜치의 다른 세션이 이미 `2ffd233`/`7e68a72`로 **시스템 PIP를 완전히
폐기하고 `SYSTEM_ALERT_WINDOW` 플로팅 오버레이로 교체**해 놓은 상태였다. 이 핸드오프의
지시(§2-1~2-4, PIP 반복 왕복)는 전부 **S3에서 이미 고쳐진 트리거**(`inactive` 오검출 →
PIP 진입)를 대상으로 한 것이었다.

판단: 낡은 전제로 계속 조사하는 대신 **현 HEAD로 재빌드해 재검증**했다(JDK21,
`adb install -r`로 앱 데이터 보존 확인).

## 재검증 결과

- **노티피케이션 트리거(구 버그)**: 현 HEAD에서 완전 무반응 확인 — S3의 "라이프사이클
  오검출 근원 제거" 수정이 실기기에서 검증됨.
- **실제 트리거(HOME 키 → 오버레이 표시 → 아이콘 1탭 복귀)**: 단발 1회 + 반복 15회
  + 장기체류(2분20초) 1회 = **17회 왕복 전부 백화 없음.** `onMapCreated`는 최초
  진입 1회만 호출되고 이후 재호출 0건, `MissingPluginException` 0건.
- **§3 가드 결함**(`_locLayerReady`/`_destLayerReady` 미리셋)은 코드에 **여전히 존재**하지만,
  그걸 발현시키던 유일한 확인 경로(PIP 진입 시 윈도우 리사이즈→네이티브 서피스 파괴)가
  S3b에서 메커니즘째 사라져 **실질적으로 트리거 불가 상태**가 됐다. "고쳤다"가 아니라
  "트리거가 없어졌다"는 것 — 근본 수정(가드 리셋)은 여전히 권장 사항으로 남는다.
- **속도계·일출일몰 축**: 같은 17회 전부 무결함. 별도로, 반복 중 카메라 접근 경고
  게이지(로드맵 18번)가 실제 발동해 속도계 자리를 대신 채운 것을 백화로 오인할 뻔했다 —
  확인 결과 정상 동작이었다.
- **메모리 압박 축**: `am send-trim-memory`가 4회 전부 OS에 의해 거부됨
  (`foreground process에는 background trim level을 설정할 수 없다`) — `NavForegroundService`가
  살아있는 한 강제 trim 대상이 아니라는 뜻. 진짜 압박(다수 실앱 백그라운드)은 마스터
  실사용 폰이라 시도하지 않음.
- **[범위 밖 신규 발견]** `StreamSink is bound to a stream` 크래시 1건 관측(HOME 복귀 후
  ~1분37초). 재현조건 미확정, 원인 미조사 — 다음 세션 후보로 남김.
