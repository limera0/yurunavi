## ✅ 뭐가 됐나 (쉬운 말로)

### 1. 네이티브 로그가 이제 진단로그에 남습니다 (청크1, 최우선)
지금까지 진단로그는 Dart 쪽 로그만 담았고, **화면이 백지로 변하는 원인일 가능성이
가장 큰 Flutter 엔진(Impeller/Vulkan) 쪽 로그는 하나도 안 남았습니다**(95k줄 뒤져도
매치 0건이었습니다). 이제 앱 자신의 시스템 로그를 걸러서(엔진·GPU 관련 키워드만)
진단로그에 `YNAV_NATIVE` 줄로 같이 남습니다. **다음 실주행에서 백화가 재발하면, 그
순간 진단로그에 `Could not create valid atlas` 같은 줄이 있는지가 원인을 확정짓는
결정적 증거가 됩니다.**

### 2. 메모리를 덜 쓰도록 여러 군데를 고쳤습니다 (청크2~5)
- 이미지를 그릴 때 쓰고 버리지 않던 임시 자원(`ui.Picture`) 3곳을 정리했습니다.
- 이미지 캐시 상한을 기본값(1000장/100MB)에서 실사용 규모에 맞게 40장/20MB로
  크게 줄였습니다.
- 안드로이드가 "메모리 부족해!"라고 신호를 보내거나(OS 메모리 경고), 앱이
  백그라운드로 갈 때 이미지 캐시를 자동으로 비우도록 했습니다. (레퍼런스 앱
  OsmAnd/Organic Maps는 이미 다 하고 있던 것들입니다.)
- 안 쓰이는 죽은 지도 라이브러리(`flutter_map`)를 통째로 뺐습니다 — 실제 지도는
  전부 네이티브 MapLibre라 이 라이브러리는 애초에 동작한 적이 없었습니다.

### 3. 지도 화면이 재생성될 때 퍽·핀이 사라지던 결함을 고쳤습니다 (청크4)
드물게 지도(플랫폼뷰)가 다시 그려지는 상황(스타일 재적용 등)이 생기면, 내 위치
표시(퍽)와 목적지/경유지 핀이 **새 지도에 다시 설치되지 않고 사라지는** 결함이
있었습니다. 이미 다른 화면(장소 검색 화면)엔 이 문제를 고친 코드가 있었는데,
내비게이션 화면에는 빠져 있었던 걸 찾아서 똑같이 적용했습니다. (부수 효과: 체크리스트
S8 "주유소 경유지 마커 미표시" 결함의 원인 중 하나이기도 했습니다.)

### 4. GPU 메모리 사용량을 실주행에서 자동으로 기록합니다 (청크6 B-2)
예전엔 이 정보를 얻으려면 기기를 컴퓨터에 연결해서 명령어로 찍어야 했는데, 이제
앱이 스스로 60초마다 자기 GPU/전체 메모리 사용량 근사치를 진단로그에 남깁니다.
**마스터가 평소 타던 대로만 타도 시계열 데이터가 자동으로 쌓입니다.**

### 5. Impeller(렌더 엔진) 끈 판별용 APK를 별도로 만들었습니다 (청크6 C-1)
`outputs/yurunavi_impeller_off_diag_20260806.apk` — **이건 해결책이 아니라 원인
판별용입니다.** 백화의 유력 원인이 Impeller(안드로이드의 새 렌더링 엔진) 계열
버그라서, 이 APK로 한 번 주행해서 백화가 안 생기면 원인이 Impeller임이
확정됩니다. **평소 쓰는 앱과 별도로, 딱 1회 판별용으로만 써주세요** — 이 설정을
기본값으로 채택한 게 아니라서 코드에는 반영 안 했습니다.

## 지시서 대비 정정한 것 1건 (정직하게 기록)

청크4(A-5)에서 지시서(§5)는 리셋 지점을 `onMapCreated`(nav_screen.dart:1931)로
추정했습니다. 그런데 지시서가 시킨 대로 `main_map_screen.dart`에 같은 패턴의 가드가
있는지 직접 확인해보니, **거기엔 이미 이 문제를 겪고 고친 코드가 있었고, 리셋 지점은
`onMapCreated`가 아니라 `onStyleLoadedCallback`(스타일 로드 콜백) 맨 앞**이었습니다.
이유: 스타일 재주입은 지도 플랫폼뷰 전체가 다시 만들어지지 않아도 일어날 수 있고,
그때도 네이티브 레이어·심볼이 사라지기 때문입니다. 검증된 실제 동작 코드를 근거로
지시서보다 이쪽을 따랐습니다 — 결과적으로 더 넓은 시나리오(스타일 재주입만 / 플랫폼뷰
전체 재생성 둘 다)를 커버합니다.

## 청크4 감사에서 나온 후속 확인 사항 (막지는 않음, 기록만)

`_initRouteLayer()`/`_initPoiLayer()`/이번에 리셋이 추가된 `_initLocationLayer()`/
`_initDestLayer()` 체인은 **동시 재진입을 막는 장치(뮤텍스/세대 토큰)가 원래부터
없습니다.** `_onStyleLoaded()`가 아주 짧은 시간에 두 번 연속 발화하면(직전 호출의
비동기 체인이 안 끝난 채로) 레이어가 중복 설치될 이론적 위험이 있습니다. 실기기
증거(§10-1-B, S3b 이후 17회 왕복)로는 이런 연속 발화가 관찰된 적이 없어 이번엔
손대지 않았습니다 — **다음에 지도 재생성 관련 이상 증상(레이어 중복, 예외)이 보이면
이 지점을 의심해볼 것.**
