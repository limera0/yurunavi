# RECON — LLM-Wiki 통합 세션 아카이브 구축 방안

작성 2026-08-03 · 상태: **1단계 완료 (P1a~P1e 전부)** · 2단계 웹 UI 대기

목표: 모든 Claude Code 세션 + 타 LLM 대화를 한 곳에 모아 주제 트리·태그·검색으로 관리하고,
Claude Code가 알아서 참조해 **초기 컨텍스트를 줄이면서 누락은 없게** 만든다.

## 0. 조사로 뒤집힌 전제 3가지

### (1) "Discord 세션은 어디서도 못 본다" → **틀렸다. 전부 디스크에 있다.**

`~/.claude/projects/-data-projects-yurunavi/` 에 **495개 jsonl · 469MB**(루트 167 + 서브에이전트 328).
VS Code·Discord·야간루프가 전부 같은 저장소를 쓰고, `entrypoint` 필드로 구분된다:

| entrypoint | 줄 수 | 정체 |
|---|---|---|
| `claude-vscode` | 34,594 | VS Code 확장 세션 |
| `sdk-cli` | 6,186 | `claude -p` — **Discord 봇 + `run_night_auto.sh` 야간루프** |
| `cli` | 587 | 터미널 직접 실행 |

→ **데이터 유실이 아니라 열람 수단 부재다.** 만들 것은 수집기가 아니라 뷰어·검색기이며,
   과거 4개월치가 1일차부터 조회된다. `aiTitle`(세션 제목)도 이미 자동 생성돼 있어 그대로 쓴다.

### (2) "세션 트리" → **원본에 부모-자식 관계가 거의 없다.**

실측으로 확인된 연결선은 2종류뿐이다:
- **서브에이전트**: `<세션ID>/subagents/agent-*.jsonl` (63디렉토리·328파일) — 확실한 부모-자식
- **컴팩트 경계**: `logicalParentUuid` + `compactMetadata` (16건) — 같은 파일 내 이어짐

반면 **세션 간 `parentUuid` 교차 링크는 167개 루트 세션 중 0쌍**이다. `--resume`가 히스토리를
새 uuid로 복사한 독립 파일을 만들어 계보가 끊긴다.

→ 트리는 자동 생성이 불가능하다. **자동 간선(기계)** 과 **주제 트리(사람이 승인)** 를
   별도 테이블로 분리해야 한다. 한 덩어리로 두면 재색인이 사람 배치를 덮어써 망가진다.

### (3) "N8N LLM-Wiki를 한 번도 안 썼다" → **이유가 2개, 둘 다 구조적이다.**

- **출구가 없다.** 워크플로 `FwHfnx3RP4lurx2v`는 `Discord 웹훅 → 스크랩 → 요약 → md 기록`이
  전부다. 검색·목록·Claude 연동이 없다. 안 쓴 게 아니라 쓸 방법이 없었다.
- **엔진이 죽어 있다.** `/data/wiki/schema.md`가 주 엔진으로 지정한 `phi4-mini:latest`가
  ollama에서 사라졌다(현재 `llava`, `bge-m3`뿐). 설계상 로컬 경로가 통째로 무효인 채
  OpenRouter 폴백으로만 연명 중이었다. 누적 산출물 15건이 그 증거다.

→ 이번 구축의 무게중심은 **입력이 아니라 조회**에 둔다.

## 1. 로컬 모델 실측 검증 — 둘 다 요약·태깅 불가 (2026-08-03 확인)

마스터 지시로 기존 ollama 자산을 먼저 검토했다. 추측이 아니라 실제 호출 결과다.

### bge-m3 — 생성 원천 불가 + **GPU 경로 NaN 결함**

생성은 모델 구조상 불가능하다. ollama가 직접 거부한다:
```
{"error":"\"bge-m3\" does not support generate"}
```

임베딩에서는 별도 버그를 발견했다 — **130자를 넘으면 NaN + HTTP 500**:

| 입력 길이 | GPU(기본) | CPU 강제(`num_gpu:0`) |
|---|---|---|
| 130자 | ✅ | ✅ |
| 160자 | ❌ NaN | ✅ |
| 735자 | ❌ NaN | ✅ |
| 1380자 | ❌ NaN | ✅ |

ollama 로그: `llm embedding error: failed to encode response: json: unsupported value: NaN`.
**RTX 2060 GPU 가속 경로에서만** 발생한다. 그대로 의미검색을 붙였다면 *짧은 쿼리는 되는데
문서 색인만 통째로 실패하는* 원인 찾기 고약한 형태로 터졌을 것이다.

CPU 속도 실측 1000자당 2.48초 → 전체 백필 **43시간(단일) / 11시간(4병렬)**.

→ **의미검색용으로는 살릴 수 있다(CPU 강제 필수). 요약·태깅용으로는 불가.**

### llava — 생성은 되나 지시 불이행

실제 세션 발췌로 "3줄 요약 + 태그 5개"를 요청한 결과: 요약이 아니라 **입력 문장을 그대로
되풀이**했고 **태그는 0개**. 형식 지시를 전혀 안 지켰다. 2023년 비전 모델(llama 7B 기반)이라
한국어 지시추종이 약하다.

→ **세션 요약·태깅에 부적합.** 다만 이미지 설명은 본업이므로 3단계 스크린샷 처리용으로 보존.

### SQLite FTS5 한국어 검색 — trigram 사용 가능, 단 2글자 함정

SQLite 3.45.1, `tokenize='trigram'` 동작 확인. 단어 중간 일치(`루나비` → 히트)까지 된다.
**단, trigram은 3글자 미만 쿼리를 못 받는다** — `유턴`·`지도`·`마커` 같은 흔한 2글자
한국어 검색어가 0건이 된다. → 2글자 이하는 `LIKE '%…%'` 폴백(5만행 13ms, 실사용 충분).

## 4. 1단계 상세 설계

### 4-1. 디렉토리 배치

```
/data/wiki/                    NVMe — 인덱스·코드·설정
├─ wiki.db                     SQLite (세션·메시지·문서·태그·트리)
├─ tree.yaml                   주제 트리 정의 ★사람이 읽고 고치는 단일 소스
├─ tags.yaml                   통제 어휘 태그 목록
├─ index.md · log.md           기존 유지(호환)
├─ schema.md                   갱신 필요 — phi4-mini 기술이 무효
└─ bin/
   ├─ wiki-index               증분 색인기 (jsonl + md)
   ├─ wiki-classify            claude -p 분류·요약·태깅
   ├─ wiki                     조회 CLI (search / show / toc / tree / tags)
   └─ redact.py                비밀정보 마스킹

/archive/wiki/                 HDD — 원본·노트 (Obsidian 볼트, Syncthing 동기화)
├─ sessions/<프로젝트>/<날짜>-<제목>.md   ★신규: 세션 요약 노트 (요약·태그·링크만)
├─ chats/                      3단계 타 LLM 대화 (현재 0건 — 이미 준비된 자리)
└─ entities/ topics/ notes/ web/ youtube/   기존 유지
```

### 4-2. 트리 모양 (확정 골격 — 하위는 재분석으로 채움)

```
📁 유루나비                       ← 프로젝트
   ├ 내비게이션 엔진
   │    ├ 라우팅/코스팅  ├ 안내/음성  └ 구조물 인지
   ├ 앱 UI
   │    ├ 화면 레이아웃  ├ 계기판     └ 브랜드/스킨
   ├ 데이터/POI
   ├ 검증/실주행
   └ 인프라/운영
📁 (향후 프로젝트: hm-tracker 등)
📁 지식/레퍼런스                  ← 프로젝트 무관
   ├ AI/에이전트  ├ 개발일반  └ 오토바이/투어
📁 일상/기타
```

`tree.yaml` 하나가 단일 소스다. 재색인은 **노드 배치를 절대 건드리지 않고** 새 항목만 미분류
대기열에 넣는다. 기존 `WIKI_INDEX.md` 19개 평면 카테고리는 이 3단 트리로 흡수된다.

### 4-3. DB 스키마 (SQLite)

```sql
sessions(id, source, project, cwd, branch, entrypoint, title, summary,
         started_at, ended_at, msg_count, char_count,
         parent_session,              -- 서브에이전트 부모
         hidden,                      -- 소프트 삭제(원본은 안 지움)
         file_path, file_mtime, file_offset)   -- 증분 색인 커서
messages(id, session_id, uuid, parent_uuid, role, ts, text, tool_name, is_sidechain)
docs(id, path, title, mtime, body)   -- loop/*.md 248개 + /archive/wiki/**
nodes(id, parent_id, name, sort)     -- tree.yaml 투영
items(node_id, ref_kind, ref_id)     -- 세션·문서를 노드에 배치(다중 배치 허용)
tags(id, name)
item_tags(ref_kind, ref_id, tag_id, confidence, by)   -- by: auto|human ← 중복 태깅
fts_messages, fts_docs               -- FTS5 trigram
```

### 4-4. Claude 자동 참조 방식 (MCP 불필요)

- **SessionStart 훅** → `wiki toc` 출력 약 20줄 주입: 트리 목차 + CLI 사용법 3줄.
- **조회**는 Claude가 필요할 때 Bash로 `wiki search "유턴" --tag 라우팅` 실행.
  현재 MCP 서버가 0개인데, 1단계는 CLI만으로 충분하고 `claude -p` 무인 틱에서도 그대로 돈다.
  (MCP는 2단계 웹 UI 때 재검토)
- **SessionEnd 훅** → 해당 세션 즉시 색인.
- **cron 15분 스윕** → 비정상 종료로 훅이 안 뛴 세션 보정.
- 기존 `commit-gate.sh`(PreToolUse)와 병존 확인 필요.

### 4-7. P1b 실행 결과 (2026-08-03) — 마스터 승인 완료

`bin/wiki-tree` 신규 (`digest` / `draft` / `show` / `apply` / `assign` / `audit`).
세션 167 + 문서 267을 30KB 다이제스트로 압축 → `claude -p` → `tree.yaml`.

**확정 트리**: 최상위 4개(유루나비 / 기타 프로젝트 / 지식·레퍼런스 / 일상·기타) ·
중분류 17개 · 잎 50개. 커버리지 세션 167/167 · 문서 266/267(미분류는 50자 테스트 노트).

**키워드 배치 점수를 두 번 고쳤다** — 둘 다 이 코퍼스 특유의 함정이다:
1. 본문 키워드 *빈도*로 세니 긴 세션이 독식(한 잎이 434건 중 80건). 긴 대화일수록
   온갖 낱말이 한 번은 나온다 → 빈도 대신 *등장한 키워드 종류 수*, 제목에 3배 가중.
2. 그래도 한 잎이 115건. 범인은 LLM이 고른 키워드 `loop` — 이 저장소에선 디렉토리
   이름이라 거의 모든 세션에 나온다 → **IDF 가중** 도입, 코퍼스 40% 초과 등장
   키워드(gps·loop·poi·valhalla 등 15개) 자동 제외. 최대 잎 115 → 51로 평탄화.

**흔적 제거(스크럽) 기능 추가.** 마스터 지시로 폐기 주제를 색인에서 제거했다.
`scrub.txt`(gitignore 대상 — 지울 낱말을 저장소 히스토리에 남기지 않으려는 것)에
낱말을 적으면 색인 전 마스킹되고, 세션 단위는 `hidden` 플래그로 숨긴다.
36개 세션에 흩어져 있었으나 대부분 무관한 작업 중 스친 언급이라, 전용 세션 2건만

### 4-9. P1d·P1e 실행 결과 (2026-08-03) — **1단계 완료** · code-auditor PASS

저장소 디렉토리명 인코딩이 일치하는 조상만 인정하도록 `wiki-index`와 규칙을 통일했다.

## 5. 2·3단계 개요

- **2단계 — 웹 UI**: FastAPI + 단일 페이지(좌 트리 / 우 트랜스크립트 / 상단 검색·태그칩),
  트리 드래그 재배치·숨김, `n8n_nginx`+`cloudflared`로 공개. **인증 필수**(6번 참조).
  이 시점에 의미검색(bge-m3 **CPU 모드** + Qdrant) 백필을 야간 배치로 돌린다.
- **3단계 — 타 LLM 통합**: ChatGPT는 `conversations.json` 내보내기가 가장 쉽다.
  Gemini는 Google Takeout HTML 파싱. Grok은 공식 내보내기가 없어 **기존 Discord 위키 채널
  붙여넣기 → `discord_wiki_relay.py` → 동일 스키마** 경로를 재활용한다. `/archive/wiki/chats/`가
  이미 비어 있는 채로 준비돼 있다. 완벽한 자동 동기화를 노리지 말고 주기적 수동 내보내기 +
  자동 취합이 유지보수가 싸다. 이미지 자료는 `llava`로 설명 생성 후 색인.

## 7. 미결·리스크

- **범위 해제 필요**: CLAUDE.md 하드룰이 "이 저장소 밖 변경 금지"인데 이 작업은

  알림만 맡기고 핵심 색인·검색은 Python으로 간다. 기존 LLM-Wiki 워크플로는 폐기가 아니라 축소.
