## 1. 라이프사이클 오검출 회귀 방어 (S3 청크1 관련)

주행 중 다음 조작을 각 **5회씩** 반복하고, **플로팅 오버레이가 뜨거나 안내가 끊기지 않아야** 한다 (이전엔 시스템 PIP로 튀어 안내가 끊겼음).

- [ ] 알림창 내리기 · 올리기 5회 → 플로팅 오버레이 표시 **0회**
- [ ] 스크린샷 5회 → 플로팅 오버레이 표시 **0회**
- [ ] 엣지패널(측면 스와이프) 5회 → 플로팅 오버레이 표시 **0회**

## 2. 정상 백그라운드 전환 & 플로팅 오버레이 복귀 (S3b 청크2 관련)

- [ ] 내비 시작 → **홈 버튼 1회** → 다른 앱(카카오톡·네이버지도 등) 열기
      → 카카오톡 화면 **위에** 유루나비 플로팅 아이콘이 뜨는지
- [ ] 그 플로팅 아이콘 **1탭** → 유루나비 앱이 포그라운드로 **즉시 복귀**
      (시스템 PIP처럼 "미니창 탭 → 복원 버튼 추가 탭" 2단계 조작이 필요하면 실패)
- [ ] 복귀 직후 플로팅 아이콘 **자동 해제** (좀비 오버레이 없음)
- [ ] 내비 종료(도착 or 뒤로가기) → 오버레이 잔존 여부 확인 → **잔존 없어야 함**

## 3. 첫 실행 UX — SYSTEM_ALERT_WINDOW 권한 안내

- [ ] 앱 최초 진입 또는 첫 내비 시작 시 **권한 요청 다이얼로그**가 뜨는지
      (제목: "화면 위에 안내 표시 권한이 필요합니다")
- [ ] [설정 열기] 탭 → 시스템 설정의 "다른 앱 위에 표시" 화면으로 이동
- [ ] 권한 켜고 앱 복귀 → 이후 홈 버튼 시나리오(§2)가 정상 작동
- [ ] [나중에] 탭 시 앱은 정상 동작하되 백그라운드에서 오버레이만 안 뜨는지
      (안내 알림 자체는 계속 떠야 함)

## 7. 메모리/GPU 압박 대응 검증 (0806 memory_hardening 세션, 커밋 `c761759`~`b906e44`)

백화(화면 서브트리가 통째로 안 그려지는 현상) 원인 확정을 위한 계측과, 레퍼런스 앱
대비 없던 메모리/GPU 압박 대응 4종을 구현한 세션. §1~6과 별개 주제이지만 한 번의
실주행에서 같이 확인 가능해 이 파일에 합친다.

- [ ] **[핵심] 진단로그에 새 접두어 3종이 실제로 남는지** — 주행 후 앱 진단로그
      파일(`ynav_*.log`)을 열어 `YNAV_NATIVE`(네이티브 엔진 로그, 정상 상태라면 안 찍혀도
      무방) / `YNAV_MEMPRESSURE`(OS 메모리 경고 또는 백그라운드 진입 시에만 찍힘,
      §2 홈 버튼 시나리오 수행 시 최소 1줄은 나와야 함) / `YNAV_GPUMEM`(60초마다 자동,
      **주행 1분만 넘어도 반드시 찍혀야 함**) 세 줄이 확인되는지.
- [ ] **[핵심] 백화 재발 여부** — 이번 세션 이전에 겪었던 화면 일부(속도계·DaylightBar
      내부 등)가 백지로 보이는 현상이 재발하는지. **재발한다면 그 시점 근처 진단로그에
      `YNAV_NATIVE` 줄 중 `Could not create valid atlas`/`Impeller`/`Vulkan`/
      `GL_OUT_OF_MEMORY` 관련 문구가 있는지** — 있으면 원인이 GPU 자원 할당 실패임이
      확정된다(로그를 다음 세션에 그대로 전달해줄 것).
- [ ] 내비게이션 화면에서 **내 위치 표시(퍽)와 목적지/경유지 핀이 평소처럼 잘 보이는지**
      일반 확인 (청크4 — 지도 재생성 시 레이어 재설치 로직을 고친 변경, 이번 세션 중
      회귀 위험이 가장 높았던 항목).
- [ ] (선택, 여유 있을 때 별도로) `outputs/yurunavi_impeller_off_diag_20260806.apk`로
      **평소 쓰는 앱과 별개로 1회만** 주행 — 백화가 이 APK에서는 안 생기면 원인이
      Impeller(렌더링 엔진)로 확정된다. **이 APK는 판별용이며 채택된 해결책이 아니다** —
      확인 후 원래 앱으로 돌아올 것.

## 8. O1 · 스타일 에셋 로컬화 검증 (한글/한자 글리프 로컬 렌더링, §S3/§7과 별개 주제)

`localIdeographFontFamily`로 지도 한글·한자 글리프를 서버 대신 기기 내장 폰트로
그 자리에서 렌더링하도록 전환한 작업. **코더/하네스로는 폰트가 실제로 화면에 그 폰트로
그려지는지 육안 확인이 불가능**해서 이 목록에 넣는다.

- [ ] **iOS** — 지도 화면의 한글 지명 라벨이 정상 렌더되는지, 육안으로
      `Apple SD Gothic Neo`로 보이는지 확인(다른 폰트로 깨지거나 글리프가 네모(tofu)로
      나오면 X)
- [ ] **Android(갤럭시 우선)** — `sans-serif` 별칭 사용 시 One UI 기본 폰트로 한글이
      정상 렌더되는지 확인. 갤럭시가 아닌 기기가 있다면 그 제조사 기본 폰트로 자연
      대체되는지도 함께 확인
- [ ] **Android 설정 화면** — "설정 → 앱 설정" 하단 지도 한글 폰트 선택 항목이 보이는지
      (iOS에선 이 항목 자체가 안 보여야 정상 — 나타나면 버그)
- [ ] **Android 폰트 변경 반영** — 설정에서 다른 폰트로 변경 → **지도 화면을 한 번
      닫았다 다시 열었을 때** 변경이 반영되는지(즉시 반영은 설계상 안 됨 — 재진입 안
      해도 바뀌면 오히려 이상, 재진입해도 안 바뀌면 X)
- [ ] **Android 폰트 목록 폴백** — 목록에 최소 "시스템 기본" 1개는 항상 뜨는지
      (기기에 따라 `fonts.xml` 파싱이 실패해도 빈 화면이 아니라 이 항목으로 폴백해야 함)

## 알려진 리스크 · 사전 공지

- **API 26~30 기기(Android 8~11)에서 전화 수신 시 Auto-PIP 미작동**:
  Auto-PIP는 API 31+ 전용이라 구형 기기에서는 홈 버튼처럼 자발적 배경 전환만
  플로팅 오버레이 트리거가 된다. 전화 수신 같은 시스템 인터럽션은 커버 안 됨 —
  **의도된 트레이드오프**로 진행. 실 사용에서 문제 되면 별도 세션에서 재개.
- **드래그 이동·크기 조절·설정 UI**는 v1 스코프 밖. 오버레이 위치는 화면 우측 상단 고정.
- **Play 심사 대비 SYSTEM_ALERT_WINDOW 사용 목적 소명 문구**는 개인정보처리방침 3중 동기화 필요 —
  다음 세션 스코프.
