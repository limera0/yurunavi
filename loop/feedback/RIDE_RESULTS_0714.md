**원인 재분석** (`slider_button-3.1.0/lib/src/slider.dart` 패키지 소스 재확인):
- 이 패키지는 내부적으로 Flutter의 `Dismissible` 위젯을 그대로 사용함
  (`slider.dart:157`). `Dismissible`은 원래 "스와이프해서 리스트 아이템 삭제"용
  위젯이라 **드래그 거리 비율뿐 아니라 놓는 순간의 velocity(플링 속도)도 함께
  판정**에 들어간다 — 정확한 위치까지 도달해도 손을 천천히 떼면 스프링백,
  거리는 못 채워도 빠르게 플링하면 통과되는 등 "아이폰 밀어서 잠금해제"류
  UX(순수 위치 기반, 관대한 판정)와 판정 로직 자체가 다른 위젯.
- `buttonWidth: 52` 추가로 실제 드래그 가능 영역(`width - buttonWidth`)이 아주
  약간 줄어든 건 맞지만(70→52, 화면폭 대비 미미한 차이), 이걸로 "훨씬 나빠짐"을
  설명하기엔 부족함 — **진짜 원인은 처음부터 이 패키지가 "슬라이드 삭제"용
  위젯이라 "슬라이드 확인" UX에 안 맞았던 것**으로 판단. 이전 세션 수정은
  코드 정적분석/산수로만 검증됐고(`BUGFIX_progress.md` 완료:9 참조) 실기기
  드래그 필감 검증이 원천적으로 불가능했던 것도 한 원인.
- **파라미터를 또 조정하는 미봉책 대신, 이 서드파티 패키지(`slider_button`)를
  걷어내고 순수 `GestureDetector`+`AnimatedPositioned` 기반 커스텀 슬라이드
  위젯으로 교체 권장.** velocity 무관, 순수 위치 비율(예: 85% 이상 밀면 확정,
  놓으면 애니메이션으로 부드럽게 완료/복귀)로 판정하면 아이폰 스타일 그대로
  구현 가능하고, 앞으로 튜닝도 우리 코드 안에서 직접 통제 가능해짐.
- 대상 파일: `lib/core/widgets/slider_start_button.dart` (전면 재작성),
  `pubspec.yaml`에서 `slider_button` 의존성 제거 가능(다른 곳에서 미사용 확인 필요).

### P0-B. 도착배너 회귀 + 경유지 재포함 버그 — 같은 근본 원인으로 추정 (4번+17번 묶음)

지나침)를 구분해서 안내하고, 이후 재탐색에서 통과/도착한 경유지는 제외되어야
한다는 요청. Organic Maps 등 참고 요청.

**코드 추적 결과** (`route_progress_provider.dart:141`,
`nav_screen.dart:305-370`):
- `arrived` 플래그는 순수 `distToDest <= _kArrivalM`(현재 활성 폴리라인 잔여거리)
  로만 판정됨 — **이 "폴리라인"이 경유지 구간 하나짜리 서브 라우트인지 최종
  목적지까지의 전체 라우트인지 구분이 없음.** 오늘 로그에서 실제로 경유지 구간이
  끝날 때마다 `YNAV_ARR`(도착) 로그와 거의 동시에 `YNAV_ROUTE`(새 라우트 로드)
  로그가 반복적으로 찍힘 — 경유지 통과 시 새 서브 라우트로 갈아타는 구조로 보임.
- `nav_screen.dart`의 `_arrived`/`_arrivalBannerVisible`/10초 자동종료 타이머
  전부 이 **구분 없는 `arrived` 플래그 하나에** 걸려있음. 즉 **경유지 구간
  종료 시에도 최종 목적지 도착과 똑같이 도착배너 로직이 발동할 가능성이 높음.**
  경유지에서 속도가 느려진 상태(신호대기, 정차 등)면 종료 게이트가 열려
  10초 뒤 `Navigator.pop()`으로 **내비 화면 전체가 꺼져버릴 수 있음** — 사용자가
  본 "카드도 안 뜨고 바로 종료"와 정확히 부합하는 시나리오(빠르게 지나가는
  경유지 전환 중 배너가 한 프레임 스치듯 렌더링되다 사라졌을 가능성 높음, 라이딩
  중엔 놓치기 쉬움).
- **결론: 4번과 17번은 같은 근본 원인(경유지 구간 종료와 최종 목적지 도착을
  구분 못 하는 구조)일 가능성이 매우 높음.** 두 개를 따로 고치지 말고 하나의
  작업으로 묶어서 처리 권장.

**필요한 설계**: 경유지 상태 머신 도입 —
1. 각 경유지에 `pending`/`arrived`(정차해서 도착 확인)/`passed`(정차 없이
   지나침) 상태 부여.
2. 경유지 반경 진입 시 정차(속도 임계값 이하로 몇 초 유지) → "경유지에
   도착했습니다" 음성 + `arrived` 상태로 마킹. 정차 없이 반경을 빠져나가면 →
   "이번 경유지를 통과했습니다" 음성 + `passed` 상태로 마킹.
3. `arrived`/`passed` 상태인 경유지는 이후 모든 재탐색(수동/자동/이탈)에서
   목적지 리스트에서 제외 — 남은 경유지 + 최종 목적지만 남겨서 재요청.
4. 도착배너/종료버튼/10초 자동종료는 **최종 목적지 세그먼트에서만** 발동하도록
   `arrived` 판정 자체에 "이게 마지막 세그먼트인가"를 추가.
5. 사용자 요청대로 **Organic Maps가 이 부분을 어떻게 처리하는지 먼저 조사**
   (오픈소스라 참고 가능) 후 설계 확정 — 다음 세션 착수 전 리서치 단계 필요.
